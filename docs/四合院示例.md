# 实例：从“做一个四合院”开始

这是空间设计示例，不是传统建筑考据或保证可直接生成的成品。所选模型以实际目录、编号、尺寸与实机检查为准。

## 第一轮先提问

用户：“我要一个四合院。”

AI：“先确认三点：①偏游览展示还是带探索解谜？②第三人称自由镜头还是固定俯视？③偏朴素生活院落还是庄重的主题场景？有参考图也可以发来，说明主要参考布局还是外观。”

假设用户选择第三人称、单人游览、白天安静生活院落，下一轮再确认规模、必须保留的空间和是否可进入房屋。没有确认的内容不能作为已知需求。

## 已确认需求卡示例

| 项目 | 示例选择 |
| --- | --- |
| 目的 | 单人游览展示，约 2–3 分钟，无战斗与解谜 |
| 镜头 | 第三人称自由镜头，转角需要留相机空间 |
| 主题 | 安静、围合、对称感；用千星现有模型表达院落关系 |
| 场地 | 初始占地 32×40 米，尺寸待原生资产小样复核 |
| 必须 | 正房、左右厢房、入口、影壁、主路、院心留白 |
| 可选 | 主树、盆栽、灯具、少量生活物件 |
| 边界 | 无可进入建筑的保证；不自动生成交互、地形与灯光 |

| 入口区 | 6 / 17 | 8×4 | 入口偏东，中央空间保持完整 |
| 影壁区 | 6 / 11 | 5×1 | 两边有绕行空间，不能堵死入口 |
| 院心与主路 | 中央区域 | 依玩家镜头调整 | 建议先留约 4 米通行带，再实机复核 |

## 搭建顺序

1. 用 `catalog_search` 搜房屋、门楼、墙、石路；记录候选真实编号、尺寸与缺项。先测一栋，确认外观、正面、脚点和碰撞。没有匹配风格就说明取舍，不大量拼白模。
2. 按确认平面放主体，保留院心与主路；先导出小样在千星测第三人称镜头，再复制成对建筑。存一个“主体”工程版本。
3. 在千星完成地面平整、必要高差与坡路；记录实际地面高度，再检查星构摆放脚点。没有需求时不要加河、山或大水面。
4. 程序化规则先只覆盖一个角落：固定种子 42，使用已确认的树/盆栽白名单，入口绕行与院心列禁区。资产数量根据实测再增加，非强制配额。
5. 远景用简洁边界与院外树冠，中景强调正房/两翼/主树，近景只在门前和停留点放细节。保持院心留白。
6. 在千星设置白天环境，检查入口到正房的明暗与目标可读性；不要把网页预览灯光当作已导出的游戏效果。
7. 按相同负载区与镜头比较主体版、造景版，记录计算/内存负载。固定布景静态导出；最后走完路线并核对碰撞和遮挡。

内置离线布局不会自动生成这张院落平面。可通过外部 AI + MCP 按方案摆放，或在编辑器俯视下手工搭建。请先阅读[使用教程](使用教程.md)与[AI 协作规范](AI地编协作规范.md)。
